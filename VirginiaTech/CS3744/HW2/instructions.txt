b.	Render the entire task data whenever there is any change in the state of the task array. This means the program should remove existing to-do items before rendering them again.

f.	If a task is overdue, the entire row for the task should use the bootstrapt class text-danger to make the text appear in red. Please assume that the due date is at the end of the day, not the start. For example, if a due date on the to-do list shows 10/10/2026, it means that the task should NOT be considered overdue until 10/10/2026 11:59:59 PM.

h.	If dueDate is null, it means that the task does not have a particular due date.
